# سجل الاختبار والإصلاح — OSINT Console

كل بند هنا **عيب حقيقي ظهر أثناء الاختبار الفعلي** وأُصلح، وليس وصفاً نظرياً.

## 1) عيوب التصميم التي جعلت المنصة «تبدو لا تعمل»
| العيب | الأثر | الإصلاح |
|---|---|---|
| لا يوجد مسح شامل، فقط وحدات مفردة | المستخدم يفتح الوحدة، ينتظر، لا يرى تقدّماً → «لا يعمل» | محرك `sweep.py`: خطة كاملة لكل نوع هدف + تنفيذ متوازٍ + حالة لكل وحدة |
| التنفيذ داخل الطلب بلا بث | المسح الطويل ينتهي بمهلة أو صفحة صامتة | مهمة خلفية + استعلام دوري كل 0.6s (يعمل خلف أي وسيط) |
| وحدات بطيئة جداً | `certs` 31s · `subdomains` 12s · `news` 71s | كاش مشترك لـcrt.sh · 4 مصادر نطاقات فرعية بالتوازي · GDELT بمهلة 12s وكاش 10 دقائق |
| الاستعلامات متسلسلة داخل وحدة IP / السمعة | 8-10s لكل وحدة | 7 استعلامات متوازية في `ip_intel`، و5 قوائم سمعة متوازية |

## 2) أخطاء برمجية ظهرت عند الاختبار
- `UnboundLocalError: need` — نقاط المسح كانت قبل تعريف الدالة داخل الموجّه.
- منطق «تخطي» كان يوسم وحدات **قابلة للتنفيذ** كـ«غير منطبقة» (المنافذ/IP).
- `NameError: _single_flight` بعد استبدال كتلة كاملة.
- محلل DER لشهادة TLS كان يقرأ خطأً بنية `RDN` → موضوع/مُصدر فارغان.
- كشف Telegram كان يعطي `unknown` للحسابات غير الموجودة.
- PDF: عدّاد الصفحات كان يفوّت `/Type/Page` بدقة.
- `[object Object]` في ملخص المسح (كان يُطبع كائن التخطي كنص).
- رابط `https://github.com` كان يُمرَّر كاسم نطاق → 3 وحدات تفشل (الآن تُطبَّع الروابط).

## 3) حدود المزوّدين المجانيين (تُدار بدل أن تُفشل المنصة)
- **GitHub API 60 طلباً/ساعة** → بديل تلقائي بقراءة HTML العام (الاسم، النبذة، المتابعون، المستودعات) + كاش 30 دقيقة.
- **Tor exit list** قد يتعذر → مصدران + كاش + طلب واحد مشترك (single-flight) بين الوحدات.
- **crt.sh / Hackertarget / GDELT** تحدّ الطلبات → إعادة محاولة، كاش، ونتيجة جزئية مع ملاحظة عربية.
- **فحص المنافذ** في بيئة سحابية يمرّ عبر وسيط يفتح كل TCP → كشف تلقائي وإيقاف الفحص بتحذير بدل نتائج كاذبة.
